This patch release stops the dedicated clock from asking for root when it does not
need it.

## Highlights

- The Yeelight address resolver now degrades through four levels ordered by cost: the
  in-process cache, the last address that worked (newly persisted across restarts),
  the configured static host, and only then `ip neigh` over root. The first three are
  plain TCP connections.
- Root had been the *first* thing tried whenever the in-process cache was empty, with
  the configured static host demoted to a fallback for a completely failed root path.
  Because that cache is memory-only, every process restart made the first use of the
  device panel fork a `su`, run a shell, and raise a superuser toast — to rediscover
  an address that DHCP changes every few months.
- The Magisk `service.d` boot helper was repaired for the phone's current firmware.
  Its MIUI-private auto-start AppOp (`10008`) does not exist outside MIUI, and the
  `magisk --sqlite` call it used to suppress the grant toast was removed in Magisk 30,
  so that step had silently been doing nothing. It now writes through `sqlite3`,
  touching only the notification column and never the grant itself.
- Documentation was rewritten around the phone's actual operating system.

## Compatibility

- Android 10 or newer
- ARM64 devices only (`arm64-v8a`)
- Tested on a rooted Xiaomi Mi 9 Pro 5G running Android 13 (TrebleDroid vanilla GSI)
- No new permission, sensor, or root requirement; root is now used strictly less than
  before

## Installation note

Download and install `Desktop-Standby-Clock-v0.1.4.apk` below. It is signed with the
same public release key as earlier releases and can update them directly. A locally
built debug version uses a different signature and must be uninstalled first;
uninstalling clears saved app settings.

The accompanying `.sha256` file can be used to verify download integrity.

---

此补丁版本让专职时钟不再在不必要的时候申请 root。

- 吸顶灯地址解析改为按代价从低到高降级四级：内存缓存 → 上次能连上的地址（本版新增
  持久化，跨进程重启有效）→ 配置里的静态 IP → 最后才是用 root 读邻居表。前三级都是
  纯 TCP 直连。
- 此前只要内存缓存是空的，第一件事就是掏 root 读邻居表，配置里的静态 IP 反而沦为
  root 整条路径都失败后的备胎。而那份缓存只在内存里，于是应用每被系统回收重启一次，
  用户第一次打开设备面板就要 fork 一个 su、跑一遍 shell，还平白多一条超级用户提示
  ——只为重新发现一个几个月才变一次的地址。
- 修好了 Magisk `service.d` 开机脚本：MIUI 私有的自启动 AppOp（`10008`）在 MIUI 之外
  根本不存在，而它用来关掉授权提示的 `magisk --sqlite` 在 Magisk 30 已被移除，那一步
  一直在空转。现在改为直接用 `sqlite3` 写库，只动 notification 一列，不碰授权本身。
- 文档按这台手机实际运行的系统重写。

当前版本仅打包 `arm64-v8a`，要求 Android 10 或更高版本，没有新增任何权限、传感器或
root 依赖，并且比以往更少地用到 root。
